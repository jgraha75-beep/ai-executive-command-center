# Verification Checklist

Before returning work as complete, confirm:

- [ ] The requested deliverable exists at the promised location.
- [ ] It meets the stated acceptance criteria.
- [ ] Facts, sources, and dates are verified or clearly marked uncertain.
- [ ] No personal facts or achievements were invented.
- [ ] No unapproved external action was taken.
- [ ] Existing unrelated work was preserved.
- [ ] The return identifies any blocker or remaining Jahmeir action.
- [ ] The correct ledger update is identified.
- [ ] If the change is durable, the component's independent version was checked in `../01_SYSTEM_REGISTRY/COMPONENT_VERSION_REGISTRY.md`.
- [ ] The version bump is justified as major, minor, or patch, and prior history was preserved.

## Additional checks for persistent system changes

- [ ] The Workflow Selection Gate category and its observable triggers are recorded.
- [ ] A verified last-known-good checkpoint exists before a meaningful structural change.
- [ ] Any canary scope, verification result, and expansion decision are recorded.
- [ ] Core Authority, Operational State, and Advisory Data remain separate.
- [ ] No calibration or raw history silently changed core routing policy.
- [ ] A fallback path remains usable without optional intelligence.
- [ ] If verification fails, the prior verified workflow or checkpoint is identified before return.
