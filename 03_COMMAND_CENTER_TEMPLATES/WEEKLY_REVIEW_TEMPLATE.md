## 7. AI operations calibration — advisory only

Review only comparable task classes that produced meaningful evidence. Aggregate routine outcomes; do not load raw histories into normal work or write narrative logs for ordinary tasks.

| Comparable task class | Routing used | Correctness / rework | Escalation usefulness | Unnecessary spend or delay | User override / downstream issue | Advisory observation |
|---|---|---|---|---|---|---|

- Core routing principles remain authoritative. Calibration may inform a recommendation but cannot change policy automatically.
- Persist detailed exceptions only for implementation failure, user override, unexpected escalation, major rework, architecture consequence, or recurring routing evidence.
- Do not compare raw success counts across unrelated task types. One unusual outcome is not a policy change.
- If evidence is contradictory or unreliable, disable calibration influence and use deterministic core routing.
- When a stable aggregate observation is worth preserving, summarize it in `02_OPERATIONAL_LEDGERS/AI_OPERATIONS_CALIBRATION.md`; do not copy raw review notes there.
